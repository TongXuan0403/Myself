## 2. 产品概述

### 2.1 产品定位

本项目是一个面向个人创作者的技术博客，主要用于：

1. 分享技术知识、项目实践和问题排查过程。
2. 记录学习过程、工具实验和个人成长。
3. 通过视觉化首页展示作者的技术方向、代表项目和内容体系。
4. 通过 Markdown、Git 和自动部署实现低成本、可追踪的持续发布。

### 2.2 核心主张

> 记录代码、项目和持续构建中的想法。

博客需要同时满足三类用户目标：

| 用户 | 主要目标 |
| --- | --- |
| 普通访客 | 快速了解作者及技术方向 |
| 技术读者 | 找到、读懂并复用文章内容 |
| 博主本人 | 快速写作、发布、更新和回溯内容 |

### 2.3 设计原则

- 内容优先：视觉设计服务于理解和阅读，不遮挡正文信息。
- 结构清晰：分类、标签、专题和搜索共同构成稳定的信息组织方式。
- 个人化：通过项目、记录、观点和视觉素材体现作者，而不只展示文章标题。
- 自动化：文章从 Markdown 到部署、分享素材生成尽量自动完成。
- 可持续：先实现稳定的 MVP，再逐步加入互动和高级视觉效果。
- 可浏览：让访客能够从最新内容、专题路线和搜索入口快速进入内容。

## 5. 页面需求

### 5.1 首页

#### 目标

让访客在一个屏幕内知道“你是谁、分享什么、最近在做什么”，并能继续进入内容。

#### 首屏内容

- 博客名称或个人名称
- 一句个人标语
- 一句不超过两行的定位描述
- 技术方向标签
- 最近项目或精选文章的视觉入口
- “查看文章”和 GitHub 两个主要行动入口

#### 内容区

1. 精选文章：展示 3 篇以内重点内容，使用封面图、分类、标题和摘要。
2. 最新文章：使用高密度列表，显示日期、标题、分类、标签和阅读时长。
3. 专题：展示 2 至 4 个内容集合，明确文章数量和完成度。
4. 项目实验室：展示项目截图、状态、技术栈和项目链接。
5. 最近记录：展示最近 3 至 5 条学习或开发动态。

#### 设计要求

- 首屏有明确的视觉焦点，但首屏高度不能阻止用户看到下一段内容。
- 精选内容可使用大图或不对称网格，最新文章必须保持快速扫描效率。
- 首页避免大段介绍文字和营销式口号。

### 5.2 文章列表页

- 支持按发布时间倒序排列。
- 支持分类、标签和专题筛选。
- 支持关键词搜索。
- 每篇文章显示标题、摘要、发布时间、更新时间、分类、标签和预计阅读时长。
- 文章封面为可选项，没有封面时使用统一的排版占位方式。
- 空状态需要说明当前筛选条件下暂无文章，并提供清除筛选入口。

### 5.3 文章详情页

#### 页面组成

1. 面包屑或分类入口
2. 标题、摘要和元信息
3. 文章正文
4. 桌面端目录
5. 代码块复制按钮
6. 图片查看和放大
7. 相关文章
8. 上一篇和下一篇
9. 更新时间和编辑说明

#### 阅读要求

- 正文内容宽度建议为 760px 至 900px。
- 中文正文行高建议为 1.8 至 2.0。
- 代码、命令和文件路径使用等宽字体。
- 标题层级必须连续，目录与正文标题保持一致。
- 外部链接在视觉上可识别，链接文本需要描述目标内容。
- 长代码行允许横向滚动，不强制破坏代码格式。
- 文章页不放置干扰阅读的自动弹窗。

#### 技术文章内容模板

```text
问题背景
技术方案
实现过程
关键代码
遇到的问题
解决方式
最终效果
总结与后续改进
```

### 5.4 专题页

专题用于把多篇文章组织成有顺序的学习或实践路径。

专题信息包括：

- 专题名称
- 一句话说明
- 封面或主题视觉
- 适合读者
- 文章数量
- 已完成内容数量
- 预计阅读时间
- 文章顺序
- 专题进度

示例专题：

```text
个人博客从零实现
├── 技术选型
├── 页面设计
├── Markdown 渲染
├── 自动部署
└── 性能优化
```

### 5.5 项目实验室

项目页重点展示真实成果，不使用只有名称和技术栈的简单项目卡片。

项目详情至少包括：

- 项目名称和一句话介绍
- 项目截图或演示视频
- 项目状态：构思中、开发中、已上线、维护中
- 技术栈
- 项目背景
- 功能拆解
- 实现过程
- 踩坑记录
- 最终效果
- GitHub 地址
- 在线预览地址
- 相关技术文章

### 5.6 记录时间线

记录页面用于呈现持续成长，不要求每条内容都写成完整文章。

记录类型包括：

- 学习笔记
- 项目进展
- 技术观点
- 工具尝试
- 问题解决
- 阶段总结

每条记录包括日期、标题、简短内容、关联标签和可选链接。

### 5.7 关于我

- 个人简介
- 技术方向
- 当前正在学习的内容
- 代表项目
- 工作或学习经历
- GitHub、邮箱和其他公开链接
- 联系方式不展示敏感个人信息

### 5.8 内容发布流

参考李勃老师网站的“最近发布”和课程系列组织方式，首页需要让新增内容成为持续更新的主线，而不是只展示固定的精选卡片：

- 使用时间倒序的最新发布流，显示日期、内容类型、标题和摘要。
- 对连续文章提供专题或系列入口，并显示文章数量和当前进度。
- 允许文章、项目和短记录进入同一个发布流，同时通过类型标签区分。
- 将搜索入口放在首页和文章页的高可见位置，支持搜索课程式的内容标题和技术关键词。
- 新内容发布后可以自动进入首页最新列表，不需要手动修改首页结构。

### 5.9 长页面叙事

参考该站点用“主张、内容区块、配图和行动入口”组成的长页面结构，项目专题页可以采用分段叙事：

1. 首屏给出专题名称、适合人群和最终目标。
2. 中段按阶段展示概念、实践任务和阶段成果。
3. 每个阶段提供文章、代码或项目结果入口。
4. 结尾提供下一步行动，例如继续阅读、查看项目或订阅更新。

页面需要保持每个区块单一重点，避免一个区块同时堆叠过多按钮、说明和装饰。

## 6. 视觉设计规范

### 6.1 整体风格

采用“编辑杂志感 + 技术文档感”的视觉方向：

- 首页具有视觉表达和内容策划感。
- 文章页保持克制、稳定和长时间阅读友好。
- 项目页强调真实截图和实现结果。
- 页面区块使用完整横向布局，不滥用嵌套卡片。
- 卡片圆角不超过 8px，除非后续建立统一设计系统。

### 6.2 色彩

第一版建议使用中性背景配一个明确的强调色：

| 用途 | 建议颜色 |
| --- | --- |
| 页面背景 | `#F5F5F2` |
| 内容背景 | `#FFFFFF` |
| 正文 | `#1D1D1B` |
| 辅助文字 | `#777771` |
| 边框 | `#D9D9D2` |
| 强调色 | `#2D6A5A` 或 `#E85D3F` |
| 代码背景 | `#202321` |

颜色需要保证文字与背景达到 WCAG AA 对比度要求。不要让整站只依赖单一蓝色或紫色层次。

### 6.3 字体与排版

- 中文正文优先使用系统无衬线字体。
- 英文标题和数字可以使用具有个性的衬线或几何无衬线字体。
- 页面标题使用清晰的字号层级，不使用随视口宽度连续缩放的字体。
- 字体字距保持默认值，避免负字距造成标题拥挤。
- 正文、代码、元信息和按钮文字需要有稳定尺寸，避免内容变化导致布局跳动。

### 6.4 图片和视觉素材

- 精选文章可以使用统一比例的封面图。
- 项目页优先使用真实产品截图和实际运行结果。
- 图片需要设置宽高比或固定容器，避免加载时页面跳动。
- 图片提供有意义的替代文本。
- 视觉素材只用于帮助识别内容，不使用暗色模糊背景遮挡实际信息。

### 6.5 动效

动效用于反馈和引导，不用于持续制造干扰。

建议加入：

- 导航项悬停状态
- 文章卡片图片轻微位移或裁切变化
- 页面进入时的轻量淡入
- 阅读进度条
- 标签和筛选状态切换
- 项目截图的平滑展开

不建议加入：

- 自动播放背景视频
- 长时间等待的页面转场
- 影响滚动速度的强制动画
- 过多粒子、光晕或装饰性 3D 元素

所有动效需要响应 `prefers-reduced-motion`。

### 6.6 新增视觉参考：学习型内容主页

李勃老师网站体现了一种适合技术博客的视觉方向：页面有明确的产品主张，但信息最终落到可学习、可实践的内容上。对本项目的具体影响如下：

- 首页首屏保留个人表达，同时增加明确的“正在构建什么”或“最近发布什么”。
- 最新文章不只使用卡片墙，也提供连续、可扫描的发布列表。
- 专题封面和项目展示可以使用更完整的横幅图，强化主题识别。
- 专题页增加阶段、目标、进度和结果，让访客知道当前所处位置。
- 图片需要服务于内容理解，可以展示真实界面、代码结果、流程图或项目现场。
- 视觉动效重点放在区块进入、内容切换、进度变化和图片展示，不使用持续干扰阅读的背景动画。

最终视觉方向调整为“编辑杂志感 + 技术文档感 + 学习路线感”。

## 7. 响应式需求

### 7.1 桌面端

- 使用主内容区和辅助信息区的网格布局。

- 内容最大宽度建议为 1200px 至 1440px。

### 7.2 移动端

- 页面切换为单栏布局。
- 顶部导航收纳为菜单。
- 文章正文宽度由左右内边距控制。
- 目录改为可展开面板。
- 精选文章卡片改为纵向排列。
- 所有按钮和可点击区域保持足够触控尺寸。
- 标题、标签和按钮文字不得溢出或互相遮挡。

## 9. 自动发布与分享

### 9.1 推荐发布流程

```text
编写 Markdown
-> 本地预览
-> Git commit
-> 推送 GitHub
-> 自动构建
-> 自动部署
-> 更新 sitemap 和 RSS
-> 生成分享图片
-> 发送发布通知
```

### 9.2 自动化要求

- 草稿不会出现在生产环境。
- 推送后自动检查 Markdown 格式、链接和图片引用。
- 构建失败时需要阻止部署，并保留可读错误信息。
- 文章发布后自动生成 canonical URL、sitemap 和 RSS 条目。
- 根据文章标题、分类和封面生成 Open Graph 图片。
- 分享图片必须在移动端和社交平台预览中保持标题可读。
- 自动化流程需要记录构建时间、提交版本和部署结果。
- 每次发布对应一个 Git commit，方便追踪和回滚。

### 9.3 分享内容

每篇文章需要提供：

- 页面链接
- 文章标题
- 文章摘要
- 封面或自动生成的分享图
- 分类和标签
- 作者信息

第一版优先支持 RSS、Open Graph 和部署通知；具体社交平台的自动发布放入后续版本。

## 10. SEO、性能与可访问性

### 10.1 SEO

- 每个页面有唯一 title 和 description。
- 文章页面使用语义化标题结构。
- 生成 sitemap.xml 和 robots.txt。
- 文章使用稳定、可读的 URL。
- 配置 canonical URL。
- 分享卡片配置 Open Graph 和 Twitter Card 元数据。

### 10.2 性能

- 优先使用静态生成或缓存策略。
- 图片采用 WebP 或 AVIF，并提供尺寸约束。
- 首屏不加载非必要脚本。
- 动画和第三方统计脚本不得阻塞主要内容。
- 文章代码高亮按需加载。

### 10.3 可访问性

- 页面使用语义化 HTML。
- 键盘可以访问导航、搜索、目录和所有操作。
- 图标按钮提供可读的 aria-label 或 tooltip。
- 焦点状态清晰可见。
- 颜色不是传达状态的唯一方式。
- 动效支持减少动态效果模式。

## 11. 推荐技术实现方向

当前仓库为空，建议采用内容优先、静态优先的架构：

- 前端：React + TypeScript
- 页面框架：Next.js 或同类支持静态生成的框架
- 内容格式：Markdown 或 MDX
- 样式：CSS Modules、Tailwind CSS 或统一的 CSS 变量体系
- 代码高亮：Shiki 或同类方案
- 搜索：首版使用构建期索引，后续根据内容规模选择客户端或服务端搜索
- 部署：GitHub Actions + 静态托管平台
- 图片：仓库静态资源或对象存储

技术选型最终需要以实际开发环境、部署成本和维护复杂度为准，不在设计阶段过早绑定具体服务商。

## 12. 分阶段实施计划

### 阶段一：内容骨架

- 初始化项目
- 建立文章、专题、项目和记录目录
- 完成首页、文章列表、文章详情和关于我页面
- 接入 Markdown、代码高亮和基础响应式布局

验收标准：可以创建一篇 Markdown 文章，并在桌面端和移动端正常阅读。

### 阶段二：视觉系统

- 建立颜色、字体、间距和组件规范
- 完成精选内容网格
- 完成项目截图展示
- 增加轻量动效和空状态

验收标准：页面具有统一视觉语言，内容清晰，关键文字和图片不重叠、不溢出。

### 阶段三：内容组织

- 增加分类、标签和专题
- 增加站内搜索
- 增加记录时间线
- 增加相关文章和阅读路径

验收标准：读者可以通过导航、分类、标签、专题和搜索找到目标文章。

### 阶段四：自动发布

- 配置 GitHub Actions
- 自动构建和部署
- 自动生成 RSS、sitemap 和分享图片
- 增加构建失败反馈和部署记录

验收标准：一次 Git push 可以完成构建、部署和分享信息生成，失败时可以定位原因。

### 阶段五：优化与互动

- 性能优化
- SEO 完善
- 评论、反馈和邮件订阅
- 数据统计
- 社交平台分发

验收标准：核心阅读流程稳定，新增功能不会影响文章加载和阅读体验。

## 13. 首版验收清单

- [ ] 首页可以展示个人定位、精选文章、最新文章、专题、项目和记录
- [ ] 文章支持 Markdown、代码高亮、目录和复制代码
- [ ] 文章支持分类、标签、草稿和发布时间
- [ ] 专题可以按照顺序组织文章
- [ ] 项目详情可以展示截图、技术栈、过程和链接
- [ ] 记录页可以按时间展示动态
- [ ] 搜索和筛选结果可用
- [ ] 移动端无横向溢出和文字遮挡
- [ ] 页面支持浅色主题，后续可扩展深色主题
- [ ] RSS、sitemap 和 Open Graph 信息正确
- [ ] GitHub push 可以触发自动构建和部署
- [ ] 构建失败时不会发布不完整页面

## 14. 设计结论

本博客不追求把每个页面都做成视觉秀场，而是将视觉表达集中在首页、专题封面和项目展示，把阅读效率集中在文章页，把持续性集中在自动发布和内容版本管理上。

最终形成的产品体验应当是：

```text
访客看到首页 -> 了解作者和方向
访客浏览专题 -> 找到完整学习路径
访客阅读文章 -> 获得清晰、可复用的技术内容
访客查看项目 -> 看到真实的实现过程和结果
作者提交 Markdown -> 自动构建、部署和分享
```
