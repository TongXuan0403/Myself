# Agent / 大模型应用开发简历重构说明

## 目标

面向中大厂的 Agent 开发、大模型应用开发岗位，把原简历从“技术名词罗列”重构为“可追问的工程证据”：突出 RAG 全链路、工具调用、模型私有化部署、后端事务边界、端到端交付和 AI Coding 质量控制。

## 事实来源与边界

- 唯一事实来源：用户提供的 `王鑫恩-大模型应用开发-简历.pdf`。
- 原 PDF 中的学校、时间、项目名称、PR 状态和指标保留为已确认事实。
- 未新增公司经历、论文、技术指标或商业上线经历。
- `resume/claim-evidence-ledger.json` 保存每条主张的来源、个人边界和面试追问点。
- 四足机器人项目未放入正式版：它是真实项目，但与目标岗位的相关度低于 Dify、RAG、语音 Agent 和 AI Coding。

## 内容重构

1. 顶部增加岗位定位和能力摘要，直接说明 Python、LLM 应用和 Agent 工程主线。
2. 将 Dify PR 前置，突出事务 / Session 边界、最小改动、CI 与开源协作闭环。
3. 将 RAG 项目改写为“问题 → 链路 → 工程实现 → 结果”，保留 40 余份文档、7B 本地模型、75% 召回准确率和 2-3 秒响应等原始数据。
4. 将语音助手项目改写为 ASR / LLM / TTS / 串口工具调用闭环，明确自然语言到设备指令的转换。
5. 将 OA 项目定位为 AI Coding 工程实践，强调需求规格、人工复核、审批状态机和权限边界，避免包装为商业项目。
6. 技能栏按“编程与后端 / Agent 与 LLM / 工程与质量”组织，区分实践技术和了解技术。
